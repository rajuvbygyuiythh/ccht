EVA is an automated chatbot for Chitchat.gg (random video/text chat
platform). It simulates a female user named "EVA" who chats with
strangers and tries to redirect them to Snapchat.
CORE PURPOSE:
- Automatically chat with strangers on Chitchat.gg
- Maintain human-like conversation using 6 unique flow types
- Redirect conversations to Snapchat at the right moment
- Scale to 1000+ concurrent browser sessions smoothly
KEY DESIGN PRINCIPLES:
- "One browser, many contexts" (2026 Golden Rule) — minimize RAM
- Adaptive resource governor — never let PC freeze
- Modular architecture — each layer is independently swappable
- Backward compatible — every upgrade degrades gracefully
- Anti-detect stealth — fingerprint spoofing, WebRTC leak blocking

File: core/resource_governor.py (~447 lines)
Tiered RAM/CPU watchdog that keeps the PC responsive under heavy load.
Driven by ThreadManager.tick() (~1s intervals), adds zero threads.
Three Tiers:
Tier 1 — THROTTLE (yellow): RAM >= mem_warn (0.65) or CPU >= cpu_warn (0.60)
- Deny new browser launches via Go engine launch gate
- Extend stagger between thread starts
- Trigger Firefox memory-minimize
Tier 2 — RECYCLE (orange): RAM >= mem_recycle (0.75)
- Close oldest N contexts (ContextPool.recycle_oldest)
- Signal Go engine to pause context creation
- Run Firefox GC
Tier 3 — REDLINE (red): RAM >= mem_redline (0.85) or free < min_free_mb (512MB)
- Kill the single most expensive browser process
- Block all new launches until pressure subsides
- Cooldown: 10s between kills
Firefox Memory Optimization (45 prefs):
- disk/memory cache enabled but capped at 50MB each
- session history kept tiny (4 entries)
- image decoded buffer capped at 50MB
- speculative loading disabled
- animations off, telemetry off
- media cache small but NOT zero (prevents blank pages)
Callbacks wired by ThreadManager:
- deny_launches_cb → Go engine launch gate
- set_launch_max_cb → restore launch cap
- recycle_contexts_cb → ContextPool.recycle_oldest
- firefox_gc_cb → ContextPool.trigger_firefox_gc
- kill_worst_browser_cb → find_and_kill_worst_browser_process
File: browser/context_pool.py (~560 lines)
The 2026 Golden Rule implementation: ONE browser, MANY isolated contexts.
Instead of launching one Camoufox browser per thread (~200-300MB each),
we launch ONE browser and create N isolated BrowserContext objects inside.
Each context has its own cookies, storage, and fingerprint.
Architecture:
┌──────────────────────────────────────────┐
│           ONE Camoufox Browser              │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐     │
│  │Ctx #1│ │Ctx #2│ │Ctx #3│ │Ctx #N│     │
│  │acc 1 │ │acc 2 │ │acc 3 │ │acc N │     │
│  └──────┘ └──────┘ └──────┘ └──────┘     │
└──────────────────────────────────────────┘
Key Class: ContextPool
- max_contexts: 50 (configurable, ~1GB per 50 contexts)
- semaphore: threading.Semaphore(max_contexts) for bounding
- _slots: Dict[int, ContextSlot] tracking all active contexts
- _browser: the single shared Playwright Browser object
- start(fingerprint, proxy): Launch shared browser
- create_context(account_key, storage_state, fingerprint, proxy) → ContextSlot
- close_context(slot_id): Close context + release semaphore
- close_all(): Close every context + shut down browser
- recycle_oldest(n): Close n oldest contexts to free RAM
- trigger_firefox_gc(): Memory-minimize all live pages
- get_live_pages(): Return all Playwright pages
ContextSlot:
- slot_id, account_key, context, page, created_at, closed, proxy
- Tracks age for oldest-first recycling
Singleton pattern: get_pool() + reset_pool()

1. ENGINE ABSTRACTION
browser_engine.py abstracts Chromium vs Camoufox so all higher-level
code works with standard Playwright Browser/Context/Page objects.
2. CONTEXT POOL (2026 Golden Rule)
One browser, many isolated contexts. ~1/100th memory cost vs per-thread
browsers. Bounded by semaphore, thread-safe via RLock.
3. RESOURCE GOVERNOR (Tiered Watchdog)
Three-tier system (yellow/orange/red) driven by tick() — no extra threads.
psutil-based sampling with configurable intervals.
4. LAUNCH GATE
Go engine + ResourceGovernor coordinate to prevent too many simultaneous
browser launches that would freeze the PC.
5. STEALTH FINGERPRINTING
Coherent UA/platform/hardwareConcurrency/deviceMemory across all
navigator properties. WebRTC IP leak prevention. PluginArray spoofing.
6. NON-REPEATING RANDOM SELECTOR
Exhausts all items before repeating — ensures every template/keyword
is used before any repeats.
7. ROUND-ROBIN ACCOUNT ASSIGNMENT
AccountManager.next_idle_account() picks next idle account, skipping
banned/exhausted/failed accounts.
8. BACKGROUND TAB SIMULATION
Persistent tabs (YouTube/Reddit/Wikipedia) visited periodically with
full human-like behavior — makes browser look like real multi-tab user.
9. STYLE MIRRORING
Bot analyzes user's typing style and mirrors it (slang, punctuation,
word count, emoji density) — creates natural feel.
10. HORNEY DEFLECTION
User sends horny message → bot deflects ONCE → continues normal sequence.
Prevents sequence reset while handling inappropriate content gracefully.
11. GENTLE DEGRADATION
Every optional component (Go engine, JS worker, ContextPool, Camoufox)
degrades to pure-Python fallback if unavailable. The bot always works.
12. SIGNULED PROGRESSIVE DISCOVERY
DeviceSignin → SigninWindow → Main GUI → Bot start. Each layer unlocks
the next. Clean authentication flow.
